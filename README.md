# 🦩 Flamingo Love — GitHub Pages Edition

لعبة أسئلة لشخصين من تلفونين، بدون إعداد Backend أو قاعدة بيانات.

## النشر على GitHub Pages
1. فك ضغط `Flamingo-Love-GitHub-Pages.zip`.
2. اعمل مستودع GitHub جديد **Public** (مثلاً `flamingo-love`).
3. ارفع ملفات `index.html`, `style.css`, `questions.js`, `app.js`, `favicon.svg` إلى **جذر** المستودع (ليس المجلد الخارجي).
4. من **Settings → Pages → Build and deployment** اختر **Deploy from a branch**، ثم `main` و `/ (root)`، واضغط Save.
5. بعد اكتمال النشر، افتح الرابط الذي يظهر في قسم Pages (عادة `https://YOURNAME.github.io/flamingo-love/`).
6. على التلفون الأول: إنشاء غرفة، وعلى الثاني: فتح رابط الدعوة.

## كيفية الاتصال
نستخدم PeerJS (WebRTC) من المتصفح عبر خادم ربط عام، وليس عبر باك إند مستضاف من قبلك. يجب وجود إنترنت في الطرفين. قد تمنع بعض الشبكات الاتصال المباشر؛ هذه ليست خدمة مضمونة دائماً. ملفات PeerJS وخط Google يتم تحميلها من الإنترنت. **لا يوجد تخزين دائم للإجابات**؛ تُحفظ في ذاكرة صفحات اللعب فقط، وتضيع عند إغلاقها أو إعادة تحميلها. لا تضعوا بيانات حساسة جداً في الأجوبة. إن أردت استقراراً أكبر لاحقاً، نحتاج خدمة موثوقة/مستضافة للتزامن.

## إصلاحات الاتصال في هذه النسخة
- **المشكلة:** رسالة "الغرفة مش ظاهرة بخدمة الربط" كانت تظهر لأن اتصال صاحب الغرفة بخدمة الربط ينقطع (تبديل تطبيق لإرسال الرابط، قفل الشاشة، تذبذب الشبكة)، وصفحته ما كانت تعيد تسجيل الغرفة بشكل موثوق، أو كانت تصير مكررة الاستماع.
- صاحب الغرفة يراقب اتصاله كل ~2.5 ثانية، ويعيد الاتصال أو يعيد إنشاء نفس الغرفة بنفس الكود تلقائياً (مع تأخير تدريجي)، وأيضاً عند العودة للصفحة أو رجوع الإنترنت.
- الضيف يكمل المحاولة تلقائياً مع رسالة واضحة بدل الخطأ، ولا يقطع محاولة الاتصال قبل 20 ثانية (الاتصال عبر شبكات الموبايل قد يحتاج وقتاً).
- كشف الاتصالات الميتة (ping كل ~2.5 ثانية) وإعادة الانضمام تلقائياً بنفس الهوية: الانقطاع في منتصف اللعبة **لا يمسح التقدم** ولا يُرفض الضيف العائد.
- الضيف الثاني الغريب لا يستطيع أخذ مكان الضيف الأول أثناء اللعب.
- مكتبة PeerJS لها نسخة احتياطية من unpkg إذا فشل jsDelivr.
- إصلاح: شاشة كشف الإجابات عند صاحب الغرفة كانت تظهر "—" بدل الإجابات.

### الشبكات المختلفة (مهم)
إذا كان الطرفان على شبكتين مختلفتين وبعيدين (مثلاً شبكتا موبايل)، قد يفشل الاتصال المباشر بسبب نوع الـ NAT عند شركة الاتصالات. الحل الوحيد الموثوق هو خادم **TURN**. لا توجد خوادم TURN عامة مجانية تعمل حالياً (جرّبنا عدة خوادم وكلها لا تعمل)، لذلك افتح `app.js` وضع بيانات خادم TURN خاص بك في المتغير `TURN` بأعلى قسم الاتصال، مثلاً من حساب مجاني في Metered أو Cloudflare Calls أو خادم coturn:
```js
const TURN=[{urls:['turn:YOUR_HOST:443?transport=tcp','turn:YOUR_HOST:80'],username:'USER',credential:'PASS'}];
```
تنبيه: بيانات TURN ستكون ظاهرة في الكود للعامة؛ استخدم حساباً مجانياً/محدوداً.

## تعديل الأسئلة
من `questions.js`. كل سؤال: `know` (جواب عن النفس + توقع جواب الطرف الآخر)، `same` و `tricky` (اختيار مشترك)، أو `open` (نص حر). غيّر الألوان في `style.css`.

## حدود النسخة
- غرف مؤقتة لشخصين، من دون حسابات ومن دون حفظ سحابي.
- يبدأ صاحب الغرفة كل جلسة. إذا خرج صاحب الغرفة أو انقطع الاتصال طويلاً قد تحتاجان لغرفة جديدة.
- رموز الغرفة عشوائية، لكن ليست بديلاً عن نظام مصادقة حقيقي.
- للتجربة محلياً استخدم `python -m http.server 8000` وافتح http://localhost:8000؛ الاتصال يتطلب إنترنت.
